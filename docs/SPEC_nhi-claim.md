# 健保智慧申報 — 產品規格書

**App 名稱** 健保智慧申報（NHI Smart Claim）
**版本** v1.0 ／ **日期** 2026-07-21
**類型** SMART on FHIR 應用程式（Provider-facing, Web）
**提出單位** VtR Incorporated
**測試環境** 衛生福利部 臺灣醫療資訊標準大平台 `https://thas.mohw.gov.tw/v/r4/fhir`

---

## 1. 應用程式定位

把 EHR 中的處方資料，即時轉換成**健保申報所需的格式**——
對應健保藥品代號、中文品名、官方支付價與 ATC 分類，產出符合 HL7 FHIR R4 的 `Claim` 資源。

**核心價值：同一份臨床事實只輸入一次，申報資料由系統推導。**

本 App 執行「格式轉換與點數試算」，**不做給付核准判定**——
是否給付與實際核付金額，以中央健康保險署審查結果為準。

---

## 2. 解決的問題

| 痛點 | 現況 | 本 App |
|---|---|---|
| 病歷與申報系統分離 | 同一份臨床事實人工輸入兩次，錯漏由此而來 | 由 FHIR 直接讀取，自動轉換 |
| 院內品名 ≠ 健保品名 | 人工查對健保藥品代號耗時 | 224,455 筆官方藥品檔即時比對 |
| 藥價需逐筆查詢 | 支付價分散於公告 | 直接帶入官方支付價並試算 |
| 對應錯誤難以察覺 | 劑型／劑量對錯不易發現 | 三級品質標記，錯的不計入總點數 |

## 3. 功能規格

### 3.1 申報轉換（主頁 `#/convert`）

| 區塊 | 內容 |
|---|---|
| 病人標頭 | 中文姓名、性別、年齡、身分證字號、病歷號、診斷標籤 |
| 申報總點數 | 可定價品項之點數合計；標示可定價比例與療程天數 |
| 可直接送出比例 | 代號、劑量、劑型皆相符之品項佔比 |
| 需人工介入 | 劑型不符／劑量待確認／未對應之項數 |
| 品項點數分佈 | 依藥理類別彙總的橫條圖 |
| 對應品質 | 四級分佈環圈圖 |
| 申報品項明細 | 逐筆列出：EHR 處方（含原始編碼）→ 健保代號、健保品名、ATC、支付價、數量、小計、品質 |

**療程天數**可於畫面調整（預設 28 天），即時重算。

### 3.2 轉換規則

```
EHR 處方文字
   ↓ ① 成分辨識（學名比對 + 台灣品牌名對照表）
成分（如 clopidogrel）
   ↓ ② 查健保藥品索引
健保品項清單
   ↓ ③ 代表品項擇優：劑型相符 > 劑量相符 > 第一筆
健保藥品代號 + 中文品名 + 支付價 + ATC + 給付章節
   ↓ ④ 小計 = 支付價 × 數量（數量預設為療程天數）
申報品項
```

**代表品項擇優**採劑型優先於劑量，因為劑型錯誤（如注射劑報成口服錠）
在給藥途徑與支付價上皆為實質錯誤。

### 3.3 對應品質分級

| 等級 | 判定 | 處理 |
|---|---|---|
| **相符** | 劑型與劑量皆相符 | 計入總點數，可直接送出 |
| **劑量待確認** | 劑型相符、劑量無法比對 | 計入總點數，建議確認 |
| **劑型不符** | 索引代表品項劑型與處方不同 | **不計入總點數**，須人工核對 |
| **未對應** | 成分未收錄於索引 | **不計入總點數**，須人工對應 |

> 設計理由：申報 App 若默默把注射劑報成口服品項，是實質申報錯誤。
> 寧可標示「需人工介入」，也不製造「全部綠燈」的假象。

### 3.4 FHIR Claim（`#/claim`）

產出符合 HL7 FHIR R4 之 `Claim` 資源，可直接檢視 JSON。

| 欄位 | 內容 |
|---|---|
| `resourceType` | `Claim` |
| `status` / `use` | `draft` / `claim` |
| `type` | `pharmacy`（HL7 claim-type） |
| `patient` | 病人參照 + 中文姓名 |
| `insurance` | 全民健康保險 |
| `diagnosis[]` | 沿用來源診斷編碼（thas 為 SNOMED CT） |
| `item[].productOrService` | **同時帶健保藥品代號與原始 EHR 編碼**（雙 coding） |
| `item[].unitPrice` / `net` | 健保支付價 / 小計，幣別 `TWD` |
| `total` | 合計點數 |
| 未定價品項 | 以 `extension` 標示原因，**不靜默略過** |

**雙 coding 設計**：同一品項同時保留
`https://nhicore.nhi.gov.tw/CodeSystem/nhi-drug-code`（健保代號）與
原始 `http://rxnorm.info`（EHR 編碼），確保轉換可回溯。

### 3.5 資料來源（`#/source`）

明列 FHIR 端點、授權狀態、查詢時間與耗時、健保資料集版本、授權條款、範圍界線。

## 4. 技術規格

### 4.1 架構

```
Browser :5302 (Vite SPA, ECharts)
    │  /api/*   ← access_token 不進瀏覽器
    ▼
Backend :8802 (Node.js / Express, BFF)
    │  SMART OAuth2 + PKCE，token 僅存 server session
    │  健保藥品索引（本地，月更新）
    ▼
FHIR Server  thas.mohw.gov.tw/v/r4/fhir
```

### 4.2 FHIR 相容性

| 項目 | 規格 |
|---|---|
| FHIR 版本 | **R4 (4.0.1)** |
| 讀取資源 | `Patient`, `Condition`, `MedicationRequest`, `Observation` |
| 產出資源 | **`Claim`** |
| 存取方式 | REST GET，即時查詢，**無離線快取** |

### 4.3 使用的術語標準

| 標準 | 用途 |
|---|---|
| **健保藥品代號** | 申報品項識別（如 `A047589100` 欣血通膜衣錠75毫克） |
| **ATC** | 藥品分類（取自健保署藥品檔，如 `B01AC04`） |
| **RxNorm** | 保留 EHR 原始編碼供回溯 |
| **SNOMED CT** | 診斷（沿用來源編碼） |
| **HL7 claim-type / processpriority** | Claim 結構代碼 |

### 4.4 授權與認證（SMART App Launch IG）

| 項目 | 實作 |
|---|---|
| 授權模式 | EHR Launch（`iss` + `launch`）／ Standalone |
| 認證模式 | 公開 client + **PKCE (S256)** |
| Discovery | `.well-known/smart-configuration`，失敗退回 CapabilityStatement |
| scope | `launch openid fhirUser profile patient/*.read` |
| CSRF 防護 | `state` 隨機值 + callback 比對 |
| Token 保管 | 僅存後端 session（httpOnly cookie），**不進瀏覽器** |
| 身分識別 | OIDC `fhirUser` |

## 5. 健保藥品資料

| 項目 | 內容 |
|---|---|
| 資料集 | **健保用藥品項查詢項目檔** |
| 來源 | 政府資料開放平臺 dataset 23715（中央健康保險署） |
| API | `https://info.nhi.gov.tw/api/iode0000s01/Dataset?rId=A21030000I-E41001-001` |
| 授權 | 政府資料開放授權條款 |
| 更新頻率 | 每月 |
| 原始規模 | 224,455 筆 |
| 索引規模 | 156 種成分 / 54 藥理類別 |
| 取用欄位 | 藥品代號、藥品中文名稱、藥品英文名稱、成分、支付價、ATC 代碼、劑型、給付規定章節、給付規定章節連結 |

**索引建置注意事項**（`packages/nhi-data/src/build-index.mjs`）

| 陷阱 | 處理 |
|---|---|
| 支付價 0 = 已停止給付品項 | 排除，否則拉低中位數 |
| 成分含 `+` 為複方 | 標記 `single`，單方優先作為代表 |
| `有效迄日` 為民國年 `yyyMMdd` | 換算西元（+1911），過期品項排除 |
| 子字串比對會誤中複方 | 以成分欄比對並優先單方 |

## 8. 已知限制

| # | 限制 | 影響 | 處置 |
|---|---|---|---|
| 1 | 索引每成分僅保留代表性品項 | 特殊劑型（如 ibuprofen 注射劑）可能不在其中 | 標示「劑型不符」並排除計價，須人工核對 |
| 2 | 藥品索引涵蓋 156 種常用成分 | 罕用藥顯示「未對應」 | 依需求擴充後重建索引 |
| 3 | 數量以療程天數估算 | 未載 `dispenseRequest.quantity` 時非實際數量 | 導入時由 HIS 提供實際數量 |
| 4 | 僅涵蓋藥品費 | 未含診療項目、特材、檢驗等 | 後續介接「醫療服務給付項目及支付標準」（dataset 9405） |
| 5 | 不做給付核准判定 | 不判斷是否符合給付規定 | 依設計範圍；檢核由另一系統負責 |
| 6 | 未對應 TW Core / NHI Core IG profile | 產出為標準 FHIR Claim，未套本土 profile | 待該環境本土 IG 普及後對應 |
| 7 | id_token 未驗簽 / 無稽核紀錄 / 無 TLS | 開發環境限制 | 正式部署補齊 |

## 10. 免責

本系統執行「臨床資料 → 健保申報格式」之轉換與點數試算，
所呈現點數為依健保署公告支付價之試算結果，**非實際核付金額**。
是否給付、核付多少，以中央健康保險署審查結果為準。
標示「劑型不符」或「未對應」之品項須經人工核對後方可送出。
