# 台灣血脂 CDS — 產品規格書

**App 名稱** 台灣血脂 CDS（Taiwan Lipid CDS）
**版本** v1.0 ／ **日期** 2026-07-21
**類型** SMART on FHIR 應用程式（Provider-facing, Web）
**提出單位** VtR Incorporated
**測試環境** 衛生福利部 臺灣醫療資訊標準大平台 `https://thas.mohw.gov.tw/v/r4/fhir`

---

## 1. 應用程式定位

在醫師開立處方的當下，將病人的診斷與血脂檢驗值，
即時對照**台灣血脂治療指引**與**健保給付規定**，呈現風險分層、治療目標與現值差距。

**核心價值：把散落在指引與給付規定中的門檻，帶到需要它的時間點與畫面上。**

本 App 執行「資料呈現與門檻對照」，**不做治療方案建議**——用藥決策屬醫師職權。

---

## 2. 使用者與情境

| 角色 | 情境 | 需要回答的問題 |
|---|---|---|
| 主治醫師 | 診間看診、開立或調整降血脂藥物 | 這位病人的 LDL 該壓到多低？現在差多少？ |
| 個管師 | 慢性病追蹤 | 檢驗值趨勢如何？是否需回診衛教？ |

**典型流程**：醫師於院內系統開啟病人病歷 → 點選本 App → 系統自動帶入該病人 →
即時顯示風險分層與 LDL 目標對照。

## 3. 功能規格

### 3.1 血脂評估（主頁 `#/overview`）

| 區塊 | 內容 | 資料來源 |
|---|---|---|
| 病人標頭 | 中文姓名、性別、年齡、身分證字號、病歷號、診斷標籤 | FHIR `Patient` / `Condition` |
| 心血管風險分層 | 極高／高／中／低風險 + 判定說明 | 由 `Condition` 推導 |
| LDL-C 治療目標 | < 55 / 70 / 100 / 116 mg/dL | 指引門檻表 |
| 目前 LDL-C | 最新值、達標狀態、與目標差距 | FHIR `Observation` |
| 分層依據 | 逐條列出「哪個診斷 → 為什麼算這一級」 | 推導過程 |
| LDL 現值 vs 目標 | 橫條圖對照 | — |
| 血脂用藥與健保給付 | 藥品 → 健保代號、中文品名、ATC、支付價、給付章節 | 健保用藥品項查詢項目檔 |

**風險分層規則**

| 條件 | 分層 | LDL 目標 |
|---|---|---|
| 確診 ASCVD | 極高風險 | < 55 |
| 糖尿病 **且**（CKD 或 高血壓） | 極高風險 | < 55 |
| 糖尿病 / CKD / 家族性高膽固醇血症 | 高風險 | < 70 |
| 高血壓 或 血脂異常 | 中風險 | < 100 |
| 以上皆無 | 低風險 | < 116 |

**診斷比對方式**：以 **SNOMED CT code** 為主、**診斷文字**（中英文）為輔的雙軌比對。
> 設計理由：thas 的 `Condition` **只有 SNOMED CT，沒有 ICD-10**。
> 若僅以 ICD-10 前綴比對，在此環境永遠不會觸發。

**無診斷時的處理**：明確顯示「此病人無編碼診斷，無法可靠分層」，
不以預設低風險門檻誤導。

### 3.2 檢驗趨勢（`#/labs`）

最新值卡片 + LDL-C／HbA1c 時間序列圖。涵蓋項目：
LDL-C、HDL-C、總膽固醇、三酸甘油酯、HbA1c、空腹血糖、肌酸酐、eGFR、血壓。

### 3.3 用藥與健保對應（`#/meds`）

全部處方逐筆對應健保藥品代號、中文品名、ATC、支付價，並標示比對品質。

### 3.4 資料來源（`#/source`）

明列 FHIR 端點、授權狀態、查詢時間與耗時、健保資料集版本與授權條款。

## 4. 技術規格

### 4.1 架構

```
Browser :5301 (Vite SPA, ECharts)
    │  /api/*   ← access_token 不進瀏覽器
    ▼
Backend :8801 (Node.js / Express, BFF)
    │  SMART OAuth2 + PKCE，token 僅存 server session
    ▼
FHIR Server  thas.mohw.gov.tw/v/r4/fhir
```

### 4.2 FHIR 相容性

| 項目 | 規格 |
|---|---|
| FHIR 版本 | **R4 (4.0.1)** |
| 使用資源 | `Patient`, `Condition`, `Observation`, `MedicationRequest` |
| 存取方式 | REST GET，即時查詢，**無離線快取** |

### 4.3 使用的術語標準

| 標準 | 用途 | 實際代碼 |
|---|---|---|
| **SNOMED CT** | 診斷比對 | 44054006 第2型糖尿病、38341003 高血壓、55822004 高血脂、53741008 冠心病 |
| **LOINC** | 檢驗項目 | LDL-C **2089-1**／18262-6、HbA1c 4548-4、收縮壓 8480-6、肌酸酐 2160-0／38483-4 |
| **ATC** | 藥品分類 | 取自健保署藥品檔（如 C10AA05 atorvastatin） |
| **健保藥品代號** | 給付對應 | 取自健保用藥品項查詢項目檔 |

> **LOINC 別名設計**：同一檢驗項目在不同院所可能使用不同 LOINC 代碼。
> thas 的 LDL-C 使用 `2089-1`，國際 sandbox 常見 `18262-6`。
> 系統以別名表同時比對，避免換環境即失效。

### 4.4 授權與認證（SMART App Launch IG）

| 項目 | 實作 |
|---|---|
| 授權模式 | EHR Launch（`iss` + `launch`）／ Standalone |
| 認證模式 | 公開 client + **PKCE (S256)** |
| Discovery | `.well-known/smart-configuration`，失敗退回 CapabilityStatement |
| scope | `launch openid fhirUser profile patient/*.read` |
| CSRF 防護 | `state` 隨機值 + callback 比對 |
| Token 保管 | 僅存後端 session（httpOnly cookie），**不進瀏覽器** |
| 身分識別 | OIDC `fhirUser`（取得執行操作的醫師身分） |

## 7. 測試

| 類型 | 內容 | 結果 |
|---|---|---|
| API 整合 | 對 thas 即時查詢 → 分層 → 目標對照 | ✅ 840 ms |
| SMART EHR Launch | discovery → authorize → 醫師登入 → 病人選擇 → token → 渲染 | ✅ 見 §7.1 |
| 前端 | 四頁渲染、無 console error | ✅ |

### 7.1 SMART Launch 通過判準

不以「畫面有無內容」判定，而以下列三項同時成立：

```
1. 後端 session 持有 access_token   （/api/context → authorized: true）
2. 畫面病人來自授權後查詢           （非開放查詢 fallback）
3. 取得 fhirUser                    （OIDC 身分識別生效）
```

### 7.2 測試病人

| 項目 | 內容 |
|---|---|
| 病人 | `Patient/sun-1234567` 陳大明 · 男 · 47歲 · 身分證 A123456789 |
| 診斷 | 第2型糖尿病 (44054006)、高血壓 (38341003)、高血脂 (55822004) |
| 檢驗 | LDL-C 158.8 · HbA1c 7.7% · 空腹血糖 195.3 · 收縮壓 148.4 · 肌酸酐 0.6 |
| 預期結果 | 極高風險 → LDL 目標 < 55 → 未達標，高於目標 103.8 mg/dL |

> **診斷資料補齊說明**：該病人原無 `Condition` 資源。依官方《1014 SMART 測試環境與上架流程》
> 第 58 頁「啟動測試前，先使用 API 測試工具匯入符合 APP 使用情境之測試資料」之要求，
> 補入三筆與其**既有檢驗值及處方一致**的診斷（非虛構），並標註
> `meta.tag = tw-smart-apps-seed` 以供辨識與清除。

## 8. 已知限制

| # | 限制 | 影響 | 處置 |
|---|---|---|---|
| 1 | 風險分層僅依編碼診斷 | 無 `Condition` 時無法可靠分層 | 明確顯示「無法分層」，不給假結論 |
| 2 | 未納入吸菸、家族史等非編碼危險因子 | 分層可能低估 | 導入時由醫師補充判斷 |
| 3 | 藥品索引涵蓋 156 種常用成分 | 罕用藥顯示「未收錄」 | 依需求擴充 `INGREDIENTS` 表後重建索引 |
| 4 | 未對應 TW Core IG | 資料模型依 thas 現況（SNOMED + LOINC，無 profile） | 待 TW Core 於該環境普及後對應 |
| 5 | id_token 未驗簽 | 目前僅解析 claims | 正式部署改以 issuer JWKS 驗簽 |
| 6 | 無稽核紀錄 | 目前為 console log | 正式部署寫入 `AuditEvent` |
| 7 | 開發環境為 http://localhost | 無 TLS | 正式部署由反向代理提供 HTTPS |

## 10. 免責

本系統為臨床決策**參考**工具，呈現指引門檻與健保給付規定之對照結果，
不構成醫療建議，亦不取代醫師專業判斷。
實際給付以中央健康保險署最新公告為準。
導入前應由院內規則委員會覆核門檻設定與診斷比對邏輯。
